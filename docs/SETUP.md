# First-run setup and dependency policy

## Scope

The current release provides a **read-only diagnostic wizard**, not automatic installation. We intend first-run onboarding for users with no development tools, but implementing secure installers and checksum/provenance verification is future work.

## Windows 11

1. Install Python 3.11+ from a trusted distributor. Check `py --version`.
2. Unzip the project; in PowerShell run `py -m venv .venv`, `.\.venv\Scripts\Activate.ps1`, `python -m pip install -e .`.
3. Run `craftctl doctor` to see your JDK, Gradle, Git, Blockbench and Minecraft setup.
4. Run `craftctl ui` to open the local app. Close the terminal to stop it.
5. Create a project with simple item/block syntax. Confirm proposed scope and approve it before source generation.
6. For **building**, install JDK **25** (required to run Gradle 9.7.1 + Loom 1.18; sources compile with `--release 21`) and Gradle **9.7.1** from trusted sources, or use the wrapper generated by trusted Gradle. Avoid silently changing a separate JDK used by Minecraft/other projects.

### Project Gradle bootstrap

The generator writes `gradle/wrapper/gradle-wrapper.properties` with pinned Gradle 9.7.1 but deliberately does **not** ship `gradle-wrapper.jar`, `gradlew` or `gradlew.bat` without a sourced, checksummed wrapper. For a local trusted Gradle 9.7.1 install:

```powershell
cd "$env:USERPROFILE\.minecraft-mod-orchestra\projects\<your-mod-id>"
gradle wrapper --gradle-version 9.7.1
.\gradlew.bat build
```

To run through the application-controlled build runner, instead approve `craftctl request-build ...` and execute `craftctl build ... --approval-id ...` after wrapper/bootstrap review. **A Gradle build runs executable build scripts** and downloads libraries. It is not sandboxed in v0.1.

### Minecraft version choice

This release intentionally supports exactly **Minecraft 1.21.1 / Fabric** as a **candidate** toolchain. Version selection, newer tested profiles, managed downloads, GeckoLib profiles and migration are roadmap features. If you already have a mod targeting another version, do not import/overwrite it with this generator.

### Blockbench and Minecraft

- **Blockbench:** optional for basic static item/block source; necessary for planned advanced live 3D editing. No Blockbench plugin is installed automatically.
- **Minecraft:** launcher presence is not required to generate or compile source. Gameplay verification requires an isolated test runtime; a legitimate Minecraft account may be required to use appropriate clients.
- **GeckoLib:** not needed for static items/blocks, and not installed in generated projects. Future profiles must pin a matching GeckoLib release before enabling animated mob generation.
- **Git:** recommended for source history; no Git command is run automatically during source generation.

## Linux/macOS

Use `python3 -m venv .venv`, `source .venv/bin/activate`, `python -m pip install -e .`, then `craftctl doctor`, `craftctl ui`. For builds install a matching JDK and trusted Gradle distribution. The UI is localhost-only.

## Troubleshooting

- `craftctl` not found: activate the virtual environment and rerun `python -m pip install -e .`.
- Python `setuptools` missing: install it from a trusted Python packaging source; a fully offline bootstrap is not supported yet.
- `No Gradle wrapper or installed Gradle`: use a trusted Gradle setup as described above, then request a new build approval.
- Wrong Java major: avoid upgrading system-wide Java; select a JDK 25 installation locally to run the generated mod build (compile target stays 21).
- Blockbench missing: harmless for items/blocks; GeckoLib modeling workflow is not yet implemented.
- Existing folder error: source generation intentionally never overwrites a nonempty directory.
- `SOURCE_GENERATED_UNVERIFIED`: expected after generation. Build, test, and visual QA still need to happen.
