How this works — evidence levels and gates
Static

Files exist and match the manifest. Proves nothing about the game.

BUILD_PASS

The controller ran Gradle through the broker and it exited 0. Recorded with the JAR hash.

SERVER_BOOT_PASS

The controller started the dedicated server with the mod, saw it finish booting with no mod errors, and stopped it.

CLIENT_BOOT_PASS

You launched the game and it loaded the mod. Only you can record this.

CONTENT_VERIFIED

You saw the behaviour (item in a tab, recipe works, mob spawns and animates). Only you can record this.

Gates

Approving a spec, granting a build or server run, and recording what you saw are yours. Agents propose, implement, repair and model; they never cross a gate. A source change resets the evidence for the new source.

Mobs

Each mob starts as a placeholder. A designer agent authors the real model with the Blockbench MCP and renders previews here. Tell it what to change; your note goes into its next run.

Items & blocks

Simple items and cube blocks with placeholder textures. Recipes and block drops live in the spec (craftctl add-recipe / add-drop before generation).
